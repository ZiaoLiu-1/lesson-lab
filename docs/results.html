What each clock measures

Chrome HTTP runs from the browser request to the complete response from the local server. Server source validation is inside that HTTP duration. It is not a native trace of the separate server-to-provider connection.

Code received and checked visible use the app's per-run clock, starting before preview reset and fetch. Checked visible adds the iframe load, two animation frames and DOM/viewport checks. It is a display-availability check, not a hardware paint timestamp.

No microphone, ChatGPT Voice Chat, speech recognition or playback is included. No first-token latency, decode token rate, internal thinking stages or hardware-only speedup is measured.

The native v2 Timing panel displays 31.05 s and 2.04 s. The table retains rounded HAR durations; their additional decimals do not imply extra measurement accuracy.
